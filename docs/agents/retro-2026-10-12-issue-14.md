## Findings (by severity)

### 1. SEVERE — Test-consolidator ran Pitest, causing ~5 hour runtime

**What happened:** The `test-consolidator` subagent (step 14) ran `./gradlew pitest` to "verify" mutation metrics. With 737 mutants × 525 tests, Pitest ran for approximately 5 hours.

**Root cause:** The implement-ticket skill says step 14 should "keep the current Test coverage for each package." The consolidator interpreted "coverage" broadly and ran mutation testing, which is the **hardener's** job (step 12), not the consolidator's.

**Impact:** 5 hours of wall-clock time for a step that should take <15 minutes.

**Fix:** Update `implement-ticket` skill, step 14:

```markdown
14. /wait-subagent `test-consolidator,900` Consolidate tests: find duplicates and common bases to reduce redundancy. Make sure to
    - meet all **Acceptance Criteria** specified in the Specification and in the actual Issue.
    - keep the current **JaCoCo Test coverage** for each package (run `./gradlew test jacocoTestReport`)
    - **Do NOT run Pitest** — mutation testing was already verified in step 12 and consolidation does not change production code.
```

Also: the `900` second timeout in the skill was not enforced. The subagent ran far past it. The `wait-subagent` mechanism should hard-enforce timeouts.

### 2. MEDIUM — GitHub CLI authentication not checked upfront

**What happened:** `gh issue view 14` failed with `401: Bad credentials` because `GH_TOKEN` was invalid. The issue had to be fetched via `curl` to the GitHub API instead.

**Root cause:** The implement-ticket skill assumes `gh` works (per `docs/agents/issue-tracker.md`) but doesn't instruct checking authentication first.

**Impact:** Minor time waste at session start; workaround was found quickly.

**Fix:** Add a prerequisite check to implement-ticket step 0 (or issue-tracker.md):

```markdown
0. Verify `gh auth status` succeeds. If not, tell the user to run `gh auth login` before proceeding.
```

### 3. MEDIUM — Duplicate tests created between CompilerSpec and ParserSpec

**What happened:** The initial implementation created `ForkEndMergePumlCompilerSpec` with ~7 tests that duplicated `ForkEndMergePumlParserSpec` tests nearly verbatim (same names, same assertions, same parse calls). The code review caught this, requiring a refactor commit.

**Root cause:** The developer subagent didn't check what tests already existed in the sibling `parser/` package before writing compiler tests.

**Impact:** One extra review-fix cycle (~30 minutes).

**Fix:** Add to the developer subagent prompt in implement-ticket step 3:

```markdown
Before writing new test files, check for existing test files in sibling packages that may already cover the same scenarios. Avoid duplicating tests across parser/, compiler/, and engine/ packages.
```

### 4. LOW — GString vs String map key mismatch caused test failure

**What happened:** A parameterized test failed because `endToken.payload["action_${i}"]` used a GString key, but the payload was stored with a String key (from `.replace()`). Groovy treats GString and String as unequal map keys.

**Root cause:** Groovy gotcha not documented in the repo's test patterns.

**Impact:** One test failure, quickly fixed with `.toString()`.

**Fix:** Add to `docs/agents/quality.md` or a test patterns doc:

```markdown
## Groovy Test Gotchas

- **GString map keys**: `map["key_${var}"]` creates a GString key, which does NOT equal the String key `"key_value"`. Use `map["key_${var}".toString()]` for lookups, or use String concatenation `"key_" + var` when building keys.
```

---

### 5. LOW — Unsupported .puml files caused regression test failure

**What happened:** The initial regression test tried to parse all 10 .puml files, but 7 of them use syntax the parser doesn't support (while loops, repeat, switch, if-equals). The test had to be narrowed to only supported files.

**Root cause:** The developer didn't check which .puml files the parser actually supports before writing the regression test.

**Impact:** One test failure, quickly fixed.

**Fix:** Document supported vs unsupported PlantUML syntax in `docs/agents/domain.md` or the parser's docstring. Alternatively, the regression test should verify that existing tests pass (which is what "regression" means), not that all files parse.
